# Exigir fechas de etapa por Tipo de Proyecto — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let admins mark a Tipo de Proyecto as "requires stage dates"; for those types, undated stages disappear from both Gantt views instead of getting a placeholder date, a "pendientes de fecha" panel lists affected projects, and a navbar badge shows the total count.

**Architecture:** One new boolean column on `project_types` drives three independent, additive UI changes (two existing Gantt task-builders gain a conditional skip, one new panel, one new navbar badge) plus one new `Project` model method (`stages_missing_dates`) that the view logic and the panel both call. No validation is added — dates stay optional at the model level.

**Tech Stack:** Rails 7.2, Minitest (`ActiveSupport::TestCase`, `ActionDispatch::IntegrationTest`, `ActionView::TestCase`), PostgreSQL.

## Global Constraints

- Soft enforcement only: saving a project/stage without dates must still work, regardless of `require_stage_dates`. No new model validation on `ProjectStage` dates.
- Zero behavior change for project types where `require_stage_dates` is `false` (the default) — every existing test in `projects_controller_test.rb`, `project_test.rb`, and the admin controller tests must keep passing unmodified.
- The flag lives on `ProjectType`, not on `StageTemplate` or `ProjectStage` — spec: docs/superpowers/specs/2026-08-05-require-stage-dates-design.md.
- The navbar badge count respects `Project.visible_to(current_user)` — never shows a user projects they can't access.
- No new dependencies, no JS framework changes — this is server-rendered ERB + existing helpers only.
