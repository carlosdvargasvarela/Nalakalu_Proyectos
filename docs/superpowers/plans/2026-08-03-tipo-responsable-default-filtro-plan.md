# Tipo de responsable por defecto en el filtro Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an admin mark one `ResponsibleType` per `ProjectType` as the default responsible-type filter, mirroring `StageTemplate#default_in_filter`, and apply it on a fresh/unfiltered load of `/projects` (`build_section`) and `/projects/tracker` (`tracker`).

**Architecture:** Add `default_in_filter` (boolean) to `responsible_types`, with the same "only one default per project_type" `before_save` callback already used by `StageTemplate`. Wire the same checkbox into the admin form. In `ProjectsController#build_section`, resolve `responsible_type_id` the same way `stage_name` is already resolved (via the existing `filtered = params.key?(:status)` flag) and feed the resolved value into the `params:` hash passed to the view, since that hash also drives the Gantt color-legend logic (`section_params[:responsible_type_id]`), not just the `<select>`'s visual state. In `ProjectsController#tracker`, which has no existing "filtered" flag, use `params.key?(:responsible_type_id)` as the fresh-load signal, and thread the resolved value through a new `@responsible_type_id` ivar used everywhere the view currently reads `params[:responsible_type_id]`.

**Tech Stack:** Ruby on Rails 7.2, PostgreSQL, Minitest (fixtures, `ActiveSupport::TestCase`, `ActionDispatch::IntegrationTest`).

## Global Constraints

- Only one `ResponsibleType` per `ProjectType` may have `default_in_filter: true` — enforced by a `before_save` callback that clears any previous default in the same `project_type`, not a DB constraint (matches `StageTemplate`'s existing pattern exactly).
- The default only applies on a genuinely fresh/unfiltered load. Once the user submits the filter form — even leaving the responsible-type dropdown on "Todos" (blank) — their choice is respected and the default is never re-applied on that request.
- No new locale entries — `default_in_filter`'s checkbox label is hardcoded in the view, matching `stage_templates/_form.html.erb`'s existing (untranslated) pattern.
- Do not change `filter_by_responsible`'s signature or behavior — it already correctly treats a blank `responsible_type_id` as "no filter."

```ruby
class ResponsibleType < ApplicationRecord
  belongs_to :project_type
  has_many :project_responsibles, dependent: :destroy

  validates :name, presence: true, uniqueness: { scope: :project_type_id }

  before_save :clear_other_defaults, if: :default_in_filter?

  private

  def clear_other_defaults
    project_type.responsible_types.where.not(id: id).update_all(default_in_filter: false)
  end
end
```

```ruby
  def build_section(project_type)
    filtered = params.key?(:status)

    responsible_type_id = if filtered
      params[:responsible_type_id]
    else
      params[:responsible_type_id].presence || project_type.responsible_types.find_by(default_in_filter: true)&.id&.to_s
    end

    projects = Project.visible_to(current_user).where(project_type: project_type).includes(:project_type, project_stages: :stage_template).order(:name)
    projects = params[:status].present? ? projects.where(status: params[:status]) : projects.where.not(status: "archived")
    projects = filter_by_responsible(projects, responsible_type_id, params[:responsible_id])
    projects = filter_by_date_range(projects, params[:from_date], params[:to_date])
    projects = filter_by_query(projects, params[:q])

    projects_list = projects.to_a
    per_page = 20
    page = [params[:page].to_i, 1].max
    total_pages = (projects_list.size / per_page.to_f).ceil
    page_projects = projects_list.drop((page - 1) * per_page).first(per_page)
    stage_names = StageTemplate.where(project_type: project_type).order(:name).pluck(:name)

    stage_name = if filtered
      params[:stage_name]
    else
      project_type.stage_templates.find_by(default_in_filter: true)&.name
    end

    {
      project_type: project_type,
      params: params.slice(:status, :responsible_type_id, :responsible_id, :from_date, :to_date, :stage_name, :q, :page).merge(responsible_type_id: responsible_type_id),
      stage_name: stage_name,
      projects_list: projects_list,
      page_projects: page_projects,
      page: page,
      total_pages: total_pages,
```

(Only the `responsible_type_id` variable, its use in `filter_by_responsible`, and the `.merge(responsible_type_id: responsible_type_id)` on the `params:` hash are new — everything else in this method body is unchanged; the `.merge` overrides whatever `params.slice(...)` picked up for that key with the resolved value, so the view's `<select>` and the Gantt color-legend logic both see the resolved default, not the raw blank/missing request param.)

```ruby
  def tracker
    @project_types = ProjectType.all
    @project_type = ProjectType.find_by(id: params[:project_type_id]) || ProjectType.first
    @responsible_types = @project_type ? @project_type.responsible_types : ResponsibleType.none
    @responsible_type_id = if params.key?(:responsible_type_id)
      params[:responsible_type_id]
    else
      @project_type&.responsible_types&.find_by(default_in_filter: true)&.id&.to_s
    end
    @projects = if @project_type
      scope = Project.visible_to(current_user).where(project_type: @project_type).where.not(status: "archived")
                     .includes(project_stages: :stage_template).order(:name)
      filter_by_responsible(scope, @responsible_type_id, params[:responsible_id])
    else
      Project.none
    end
  end
```
